# HTML book spec template

The components, fragment contract and build requirements are reusable as they are. The design tokens and signature details are an EXAMPLE from the AlphaGenome book. Derive a new identity for each subject (palette, faces, one signature device drawn from the subject's own world), and replace the `SUBJECT-SPECIFIC` spots in `build/build_html.py` and `assets/book.js`.

The verified Markdown chapters (`book/chN_*.md`) are the single source of the text and code. The HTML book is **built** from them by a deterministic script, plus hand-made visual fragments. Never edit generated `*.html` chapter files by hand: edit the Markdown, a fragment, or the template, then rebuild.

## Files
```
book/
  index.html                 generated from README.md (cover + chapter list + map + notation + conventions)
  ch1_problem_and_data.html  ... ch5_training.html   (generated, same slugs as the .md)
  assets/book.css            design system (tokens, typography, components, code theme, print styles)
  assets/book.js             map renderer, predict boxes, code badges/copy, theme toggle, TOC scrollspy, reading progress, notes, mermaid/MathJax init
  build/build_html.py        md (+ fragments) → html; run: python build/build_html.py (cwd = book/, in an env with beautifulsoup4)
  build/visuals/<id>.html    one self-contained visual fragment per figure/widget (made by chapter illustrators)
  figures/*.png              real-run plots from the companion scripts (embedded as <img>)
```

## Design tokens (example; the leader decides these per subject)
- Layout concept: a reading column of ≈68ch with a sticky left rail (chapter TOC + scrollspy) on wide screens. Wide figures break out to a wider "figure band" (up to ≈1100px) with their own `overflow-x:auto`. Below 900px the rail collapses into a top "Contents" disclosure. Side gutter ≥16px at all widths.
- Type: display `IBM Plex Sans Condensed` (600/700, headings, labels, figure numbers), body `Source Serif 4` (400/600, opsz; body 18px/1.6 desktop, 17px mobile), mono `IBM Plex Mono` (code, tensor shapes, numbers in tables). All from Google Fonts with real fallback stacks. Use a fixed type scale (e.g. 1.25 ratio). Headings get `text-wrap: balance`.
- Color, light (bare `:root`): `--paper #F5F7F5` (cool off-white, slight green bias), `--panel #EBEFEC`, `--ink #17201D`, `--muted #56625D`, `--rule #D5DCD8`, `--accent #0B6E69` (deep teal: links, focus, active map node outline), `--mark #E2A21B` (amber: "you are here" highlight, predict boxes).
- Color, dark (via `@media (prefers-color-scheme: dark) :root:not([data-theme="light"])` AND `:root[data-theme="dark"]`, with `color-scheme: dark`): `--paper #0F1513`, `--panel #18201D`, `--ink #E3E9E5`, `--muted #9AA6A0`, `--rule #2A3430`, `--accent #4FC1B8`, `--mark #F2C14E`.
- Semantic nucleotide palette (figures and sequence snippets only; tokens with light/dark variants): `--nt-A` green `#2E9E5B`/`#5CCB86`, `--nt-C` blue `#2F6FD0`/`#6FA3F0`, `--nt-G` amber `#C98A0B`/`#F0B93E`, `--nt-T` red `#D2453B`/`#F07A70`.
- Body always sets an explicit `background: var(--paper)`. Every component takes colors from tokens. Never put a literal color inside a media/theme block.
- Signature details (subject-specific, used with restraint):
  1. **Resolution ruler**: a thin header strip on every chapter page, an SVG log-scale ruler 1 bp → 128 bp → 2,048 bp → 1 Mb with the chapter's resolutions highlighted in `--mark`.
  2. **Shape chips**: inline code that is a tensor shape (matches `^\(.*\)$` with commas, e.g. `(B, L, 4)`) is rendered in mono with a faint panel background and a teal underline.
  3. **Sequence snippets**: a `.dna` class colors A/C/G/T with the nucleotide tokens (use for real hg38 snippets only).
- No emoji, no gradient heroes, no cards-everywhere, no 100vh hero. The chapter opener is a compact header (chapter number in display face, title, chapter question, "This chapter covers" list) followed by the map.

## Components
- **Model map** (`<div class="ag-map" data-highlight="N2,N5"></div>`): book.js renders the README whole-model map as inline SVG from one data object (11 nodes, 14 labeled edges, the same labels as README Figure 0.1). It is laid out as a left-to-right U-Net-ish flow: input → encoder → tower⇄pair → decoder → embeddings → heads → losses → training, with data feeding losses and heads feeding evaluation. Highlighted nodes are filled `--mark`, others outlined. Every edge carries its verb label. Hovering or focusing a node shows its one-line description. Clicking a node in index.html jumps to its chapter. Text-only fallback: a `<noscript>`/hidden list of the edges as sentences.
- **Predict box**: the build turns `> **Predict.** <question>` followed by `<details><summary>Answer</summary>…</details>` into `<aside class="predict">`: amber left rule, label "Predict", the question, a `<textarea>` with a stable id (`predict-chN-k`) whose content is saved per viewer in localStorage (wrap in try/catch), and a "Reveal answer" disclosure (a native `<details>` styled). The answer stays reachable without JS.
- **Reading progress** (book.js only, no build step): chapter pages (those with `.opener__num`) save, on scroll once the page is ready (MathJax, mermaid and web fonts done), the current section (last `h2`/`h3[id]` above a reading line 25% down the viewport), where that line sits within the section as a fraction of its height, and the furthest scroll fraction, in one localStorage record per book keyed by the book folder URL. Reopening a chapter shows a fixed "Resume at <section>" pill (dismissible; hidden once the reader scrolls into that section) that restores the exact reading position, close even at another window width. index.html adds a "Continue reading" line to the cover opener, linking to `<chapter>#resume`, which restores that position directly and drops the hash, and the furthest-read percent (or "read" at ≥98%) beside each chapter link in the chapter table.
- **Notes** (book.js only, no build step): selecting text in `.main` shows an "Add note" button; the note is saved in one localStorage record per book (keyed like reading progress) as a quote anchor: exact text, 32 characters of context on each side and the old offset, so it re-anchors after a rebuild (unfound quotes stay listed). Highlights use the CSS Custom Highlight API (`::highlight(ag-note)`), so the DOM is never changed; clicking highlighted text edits the note, Delete needs a second click. Text in `script, style, textarea, svg, .mermaid, .copy, .ag-map__tip, .continue, .read-pct` is ignored. A "Notes" topbar button opens a panel listing every note in the book (jump links `page#ag-note-<id>`), with Export (Markdown grouped by chapter and section, each note also carrying its JSON record in an `<!-- ag-note … -->` comment) and Import (merges those comments by id, newer edit wins). Lazily highlighted code (`details.code-file`) re-anchors on toggle.
- **Callouts**: blockquotes starting with `**Note**`, `**Why …?**`, `**Pitfall**`, `**Biology link**`, `**Check yourself**` → `<aside class="callout callout--note|why|pitfall|bio|check">` with a small uppercase label. Pitfall uses the T-red token for its label; Biology link uses the A-green token.
- **Listings**: a paragraph `**Listing n.m** caption` (or starting `Listing n.m`) followed by a code block → `<figure class="listing" id="listing-n-m">` (lettered listings keep the letter: `listing-3-1a`) with the caption on top, the highlighted code, and a copy button. A caption that says "excerpt" or "abridged" adds the class `listing--reading` and a "for reading" tag, so the reader can tell which listings are not part of the runnable sequence. The `#1 …` footnote paragraph or list right after the block attaches to the figure as `<ol class="listing-notes">`. In code, a trailing comment `#1`, `#2` … is rendered by book.js as a small circled number badge that matches the note.
- **Equations**: MathJax 3 SVG output (`https://cdnjs.cloudflare.com/ajax/libs/mathjax/3.2.2/es5/tex-svg.min.js`; verify the URL). Display equations are centered with a numbered tag when the md numbers them. Use SVG output (not CHTML) because it needs no external fonts.
- **Code highlighting**: highlight.js 11.9.0 core + python + bash from cdnjs (verify URLs). Write the token theme yourself in book.css, using tokens, readable in both themes. Do not link an hljs stylesheet.
- **Mermaid**: blocks other than the chapter map → `<pre class="mermaid">`, rendered by mermaid 10.x from cdnjs with `theme: 'base'` and themeVariables read from the CSS tokens at load (and re-rendered on theme toggle if simple; otherwise accept a reload).
- **Figures**: `![Figure n.m takeaway…](figures/x.png)` → `<figure class="fig">` with `<img loading="lazy">` (PNG `width`/`height` read at build time, so the box is reserved before the image loads and anchor jumps do not drift) and a `<figcaption>` whose "Figure n.m" label is in the display face.
- **Visual fragments**: in the md, `<!-- VISUAL-ID: ch3-rope-dial -->` is replaced by the contents of `build/visuals/ch3-rope-dial.html`. A fragment is a `<figure class="fig fig--wide">` containing inline SVG and/or `<canvas>` plus at most one `<script>` that is scoped in an IIFE and queries only inside its own figure. It reads colors from CSS variables (`getComputedStyle`) so it works in both themes, respects `prefers-reduced-motion`, and has a `<figcaption>` stating the takeaway plus `role="img"`/`aria-label` on the SVG. Unresolved `<!-- VISUAL: ... -->` comments (ideas without fragments) are left as invisible comments.
- **Exercises**: the "Exercises" section is rendered with numbered exercise items; each "Expected observable" phrase is styled as a small label.
- **Embedded code**: each chapter ends with an appendix "Companion code" containing `<details>` blocks with the full, HTML-escaped, highlighted contents of every script for that chapter (`code/chN_*.py`, plus each shared module with the chapter that introduces it, e.g. `bookutil.py` in Ch1), read at build time. Each block has a file name header and a copy button.
- **Chrome**: a top bar with the book title (links to index.html), prev/next chapter links, and a theme toggle (light/dark/system cycling that sets/removes `data-theme` on `<html>`). A footer with prev/next. Sticky elements use `top: env(safe-area-inset-top, 0px)`.
- **Accessibility and motion**: visible focus rings (`--accent`), `prefers-reduced-motion` disables animations, color is never the only carrier of meaning, and images have alt text.
- **Print**: a print stylesheet that hides chrome, expands all `<details>`, and avoids page breaks inside figures and listings.

## Build script requirements (`build/build_html.py`)
- Use pandoc (locate it with `which pandoc`; v3+; call it by absolute path) to convert md → an HTML5 fragment: `-f markdown -t html5 --mathjax --no-highlight` (or the pandoc-3.9 equivalent), wrapping disabled. Post-process with BeautifulSoup (install `beautifulsoup4` into the alphagenome env with pip if it is missing) to apply the component transformations above, build the rail TOC from h2/h3 (ids from pandoc), and wrap the result in the page template with prev/next links.
- The chapter map: the first ```mermaid block that contains `N1` and `N10` becomes `<div class="ag-map" data-highlight="…">`, with the highlights parsed from its `style Nk ...` lines.
- Rewrite relative links `chN_*.md` → `chN_*.html`. Keep links into `../pytorch`, `../sources`, `code/` as they are.
- Deterministic and idempotent. Print one line per page written. Fail loudly if a VISUAL-ID fragment is missing. Print every listing line that is not in the companion code (the `drift` check of `build/check_listings.py`).
- Pages must work opened directly from disk (`file://`), so use no fetch() of local files; everything is inlined at build time, except figures/*.png and assets/*, which are loaded by relative path.
